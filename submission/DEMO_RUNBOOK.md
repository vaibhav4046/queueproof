# QueueProof demo runbook

## Release preflight

From the repository root, capture the intended SHA, then verify production:

```bash
git rev-parse HEAD
pnpm release:verify -- --url https://queueproof.vercel.app --sha <FINAL_SHA>
```

Open `/api/health/live` and `/api/lab`. Continue only when:

- health is live in production with exact SHA/ref, deployment ID/timestamp, and
  `grounded-grader-v2`;
- lab reports the same SHA/ref;
- Auto, Fast, Thinking, and PDF statuses used in narration are current and measured; and
- Fast/Thinking is described comparatively only when `modeComparison.comparable` is true.

## Data preflight

1. Open **Sources** and confirm at least three connector rows are currently ready with attributable
   records. Do not count a degraded or credential-only row.
2. Confirm the 346-page document receipt exposes checksum, page count, and HydraDB source ID.
3. Run the AuthShield question once. Confirm the answer is grounded/partial as supported, provider
   coverage is visible, citations resolve, and any disagreement/missing proof is visible.
4. Open the exact receipt and original link selected for the recording.
5. Confirm Today renders a useful current packet. Do not trigger an external provider write.

Respect the public query rate limit. Rehearse with enough time between repeated runs; do not create
multiple production requests merely to obtain a prettier response.

## Browser preflight

- Test the judge path at 1280×800 and 390×844.
- Check keyboard navigation, visible focus, dialog containment/restoration, Escape, and 200% zoom.
- Enable reduced motion and verify no required content depends on animation.
- Inspect console and failed network requests. Owner-only 403 responses are expected only when a
  public actor deliberately attempts a protected control; they should not be generated by normal
  public navigation.
- Verify every internal route and the selected original-source link opens.

## MCP preflight

If a real expiring token is available in the recording environment:

```bash
QUEUEPROOF_URL=https://queueproof.vercel.app node cli/queueproof.mjs mcp verify
```

Record one safe read-only tool call. Never show the environment value. If no token-backed call is
complete, describe MCP as implemented/configurable and say the authenticated client receipt is
pending. Anonymous 401 is not proof of an authenticated workflow.

## Recording order

1. Close notifications, disable password managers, and use a clean browser profile with no private
   tabs or account avatars visible.
2. Open the five canonical tabs in shot-list order.
3. Record one continuous 60-second take using [VIDEO_SCRIPT_60_SECONDS.md](VIDEO_SCRIPT_60_SECONDS.md).
4. Record a four-minute backup using [VIDEO_SCRIPT_4_MINUTES.md](VIDEO_SCRIPT_4_MINUTES.md).
5. Watch both recordings at normal speed. Check text legibility, audio, current SHA, visible
   failures, and absence of secrets.
6. Upload the selected take, set appropriate public/unlisted access permitted by the hackathon,
   and verify playback in a signed-out window.

## Failure branches

- **SHA mismatch:** stop, redeploy/verify the intended commit, then rerun measurements.
- **Artifact awaiting measurement:** run and publish the current benchmark; do not quote history.
- **Connector degraded:** keep it visible, exclude it from the count, and use only if three other
  current connectors remain proven.
- **Citation/original link fails:** choose a working current receipt or fix the release; do not hide
  the failure with a screenshot.
- **Query returns partial/abstained:** narrate the missing proof honestly. Do not rerun until a
  desired answer appears.
- **MCP unavailable:** omit the named-client claim and show the documented endpoint/security
  contract.

## Final handoff

Add the verified video URL, exact release identity, benchmark receipt, repository status, and any
remaining limitation to [FINAL_RELEASE_REPORT.md](FINAL_RELEASE_REPORT.md) and
[HACKATHON_SUBMISSION.md](HACKATHON_SUBMISSION.md).
