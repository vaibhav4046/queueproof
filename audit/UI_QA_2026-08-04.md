# QueueProof visual QA — 4 August 2026

Exact viewport checks were captured from the local production candidate through Chromium
device emulation. The page width matched the viewport at every size; no horizontal
overflow was observed.

| Viewport | Result | Notes |
| --- | --- | --- |
| 375×812 | pass | six product destinations visible; proof console stays in bounds |
| 390×844 | pass | nav targets approximately 54×46 px; 358 px console width |
| 768×1024 | pass | no overflow; product-first reading order |
| 1024×768 | pass | desktop evidence layout fits |
| 1440×900 | pass | global evidence field and calm evidence scene render together |
| 844×390 landscape | pass | no overflow |
| 390×844 reduced motion | pass | complete static text and background |
| 1440×900 reduced motion | pass | shader stays static; optional 3D scene does not mount |

Interaction checks:

- “Prove it live” focuses `#proof-question` and brings the working console into view.
- Dialog focus, Escape handling, and focus restoration remain covered by the release suite.
- Hover movement is restricted to subtle 2–4 px lift; the evidence scene has no pointer
  parallax or idle spin.
- The only browser warning observed came from an internal React Three Fiber use of the
  deprecated `THREE.Clock`; no QueueProof application errors were present.
